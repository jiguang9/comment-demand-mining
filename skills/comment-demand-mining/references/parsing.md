# 解析与归类

## 小红书复制格式

用户从小红书网页端整篇复制时，一般长这样：

```text
标题
正文（可多行）
#话题 #话题
07-12              ← 发布日期，修改过的会写"编辑于 06-19"
共 88 条评论

昵称
作者               ← 发帖人本人回复时才有
评论内容（可多行；纯图片或表情时为空）
置顶评论           ← 被置顶时才有
07-12广东          ← 日期 + 地区，地区可能缺失；也可能是"3天前河南"
137                ← 点赞数，"赞"表示 0，大数可能写成"1.2万"
15                 ← 主楼有楼中楼时是回复数；没有楼中楼、或本身就是楼中楼时是"回复"

- THE END -        ← 评论到底
```

楼中楼紧跟在它的主楼后面，内容常以"回复 某某 : "开头，但直接回复主楼的就没有这个前缀。脚本靠主楼的回复数来划楼中楼的范围；评论没有全部展开时会对不上，脚本会给出警告。

其他平台（抖音、知乎、B站、Reddit）格式各不相同。脚本解析不了时就人工解析，只要拿到四样东西就够：谁说的、说了什么、多少赞、是不是回复。

## 评论分类

一条评论可以同时属于两类。比如"我也头疼，你们用什么工具"，既是需求表达，也是求资源。

| 类别 | 怎么判断 | 用在哪 |
|---|---|---|
| 需求表达 | 讲痛点、提问、抱怨，说"有没有""怎么办""太难了" | 痛点证据 |
| 方案分享 | 分享经验、工具、流程、踩坑 | 现有方案地图 |
| 求资源 | 蹲、求、同求、求链接、求教程、求提示词、求内测、"请不要删" | 需求强度。这是最硬的信号之一，说明用户想要现成的东西 |
| 推广 | 软广、服务商、引流、接单 | 竞争格局。这类评论的赞不计入需求 |
| 共鸣 | "太真实了""我也是""收藏学习" | 弱信号，只计数 |
| 无关 | @好友、闲聊、纯图片表情 | 忽略 |

脚本的几个标记都只是关键词命中，归类时以语义为准：

- `ask`：蹲、求、同问这类。"需求"里也有个"求"字，脚本已经排除了一部分，但"老师求你保留这个帖子"其实是想收藏
- `question`：带问号、请问、怎么、有没有、"是…吗"的评论。范围宽，会混进闲聊，但能补上 `ask` 漏掉的"是免费的吗""可以借个会员吗"
- `save`：收藏、别删、严肃学习这类，说明内容值得留着照做，和求资源是两种信号

## 识别推广和水军

满足的信号越多越可疑：

- 账号名带品牌、公司名，或带"官方""工作室""AI工具""营销"等字样
- 出现"私我""私信""主页有""加V""找我""欢迎试试""我们做了"
- 留链接，或者直接报价接单
- 同一个产品被好几个账号在相近日期、用相似句式推荐。例如几天之内四五个账号都在夸同一个 PPT 工具
- 同一句话原样发了好几次。脚本摘要里的"重复内容"会列出来
- 不同账号在几天内推荐同一个产品。脚本查不出来，要自己把评论里提到的产品名按日期排一遍
- 回答不针对帖子的具体问题，用套话推荐
- 平台 AI 助手的总结式回复（如小红书的"点点"）不是真实用户，不计入需求，但它的总结可以拿来交叉对照

脚本的推广命中只是候选。像"有没有和平台合作"里的"合作"就是误判，没命中的也可能是推广（比如先说"准确率90%"，等有人问了再回"私信聊吧"）。

处理方式：疑似推广单独列一张表并写明依据。写"疑似"，不要直接断言"这是水军"。推广密集本身也是信号：说明有人在抢这个场景；如果用户还在问，说明现有产品没打动他们。

楼中楼里一长串"求提示词""求链接"，通常是某条评论挂了钩子（"私我分享"）。这说明需求强，但也可能有引流刷楼的成分，写的时候两点都要说明。

## 作者回复

作者的回复要单独过一遍，它们往往最有价值：

- 作者反复追问"具体怎么做"，说明缺的是操作步骤，不是概念
- 作者说"试过了不行""额度用完了"，是现有方案的负反馈
- 作者补充的背景（什么行业、什么任务、什么限制）决定了用户画像
