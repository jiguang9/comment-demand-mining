# 分析规则

## 需求信号强度

| 指标 | 怎么看 |
|---|---|
| 评论数和时间跨度 | 发帖几个月后还有新评论，说明一直有人搜到，是长期需求，不是一时热点 |
| 高赞评论 | 看前 3 条高赞说了什么。高赞给的是"能直接照做的东西"还是"观点"，本身就是信号 |
| 求资源数 | 蹲、求、同求的条数，以及求的是什么：教程、模板、提示词、工具、内测 |
| 作者追问 | 追问的深度和方向 |
| 推广数 | 推广多，说明有人在抢这个场景；用户还在问，说明现有产品没打动人 |
| 地区 | 集中在哪里，可能对应某个产业带或人群 |

高赞是相对概念：一条评论的赞数明显高于本帖其他评论，才算高赞。不要拿不同帖子的绝对赞数直接比较，帖子本身的流量差别很大。

挑"前 3 条高赞"之前先排除两类：

- **疑似推广**：赞不算需求，跳过它往下取，并说明跳过了哪几条
- **置顶评论**：可以算，但要提一句。置顶会放大曝光，赞数里有位置因素

## 证据强弱

| 独立证据 | 怎么用 |
|---|---|
| 1 条 | 个案，可以提，但不能单独当结论 |
| 2–4 条 | 值得关注 |
| 5 条及以上，或一条高赞 | 主要痛点 |

同一个人的多条评论只算一条；推广评论不算。挂在钩子楼下面的一串"求"（楼主写了"私我分享"之类），照样计入，但要单独列出条数并注明来自钩子楼，不要和自发的求资源混在一起，读者才能自己打折。昵称会重名（经常有好几个不同的"momo"），所以按"昵称 + 地区"区分人，脚本给出的评论人数也是这么算的。

## 时间跨度

"3天前""1天前"这类相对日期，是相对用户复制评论的那天。不知道复制日期时，把它们当作"最近还有新评论"的信号，不要换算成具体日期。

## 痛点分层

先画流程，再挂痛点，最后找空白。

1. **流程按话题来定**，不要硬套模板。做调研是"定义问题 → 找来源 → 拿数据 → 整理 → 提炼 → 落地 → 验证"，做内容可能是"选题 → 素材 → 写作 → 发布 → 复盘"。
2. **每一层写清三件事**：痛点是什么、证据（条数、短摘录、楼层）、现在有没有人解决。
3. **区分"明说的痛点"和"推断的深层需求"**。比如作者说"报告太浅"，追问里暴露出来的是"不会从数据推到原因"，后者就是推断，要写出依据。
4. **越靠前的环节越容易被忽视**。评论里的工具大多集中在中间（拿数据）和末尾（排版），流程两端常常是空白。

## 现有方案地图

列这几项：类别、评论里提到的工具或方法、解决哪一环、评论反馈（正面、负面、没说）、备注（疑似软广、未核实、有人说要付费）。

空白是指：痛点强但没有方案的环节，或者方案都被吐槽的环节。

## 机会判断

### 产品机会

每条写清楚：

- **解决哪条痛点**，附上它的证据强弱
- **给谁用**
- **现有方案缺什么**
- **复杂度**：同时满足下面四条算"简单"
  - 1 到 3 天能做出可用版本
  - 只用公开数据，或者用户自己提供的材料
  - 效果一眼能看懂，能截图对比
  - 合规风险低

  简单的建议直接做出来，拿效果发内容，因为读者更爱看做出来的东西，不爱看"我打算做什么"。有一条不满足就算"复杂"，建议先发内容验证需求，再投入。
- **风险**

优先级的粗略算法是：痛点强度 × 覆盖用户 × 竞争空白 ÷ 实现难度。结果用星级表示，附一句理由，不要假装能精确打分。

### 内容选题

每条写清楚：标题方向、接住哪条需求、形式（表格、清单、对比、教程、案例）、发出去看什么信号（收藏、求模板、追问）。

优先做"能直接抄的格式"。评论区里最受欢迎的，通常是拿来就能照着做的东西。

## 付费意愿和种子用户

- **付费信号**：评论里出现的价格、会员、代做报价，以及"太贵""公司不给买"这类说法。都要给出处，并标"未核实"。
- **种子用户**：求内测、求工具、说"我也有这个需求"的人有多少、有什么特征。默认不列昵称，也不列评论编号，因为编号同样能追到具体的人。

## 多篇综合

1. **每篇一张简报卡**：发帖人是谁、卡在哪、关键数据、最高赞说了什么
2. **用户类型对比**：几篇背后是不是同一类人
3. **共同线索**：按出现在几篇里排序（4/4 > 3/4 > …），每条线索附上每篇的证据
4. **需求地图**：环节 × 篇目 × 现在有没有人解决
5. **需求优先级、付费信号、竞争格局**
6. **产品方案**：几篇的需求如果能拆成"共用模块 + 场景模板"就这么写；附上简单和复杂产品的分流和路线
7. **内容方案和验证办法**：内容和产品怎么互相带动
8. **限制**：同一个人可能在几篇里都留了言，各篇人数相加会重复计算，这一点要写明

## 不要做

- 不把评论数当成市场规模
- 不替评论里的工具背书
- 不编造评论里没有的数字
- 不对普通用户做身份推断
